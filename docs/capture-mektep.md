# Разведка NIS mektep: перехват трафика с iPhone

Цель — узнать три вещи: **на какой хост** ходит приложение, **какая у него авторизация**
(токен с обновлением или логин-пароль с капчей) и **какие данные** оно отдаёт. Если там
токены, из проекта уходит и хранение чужих паролей, и вся возня с капчей.

iOS для этого удобнее Android: начиная с Android 7 приложения не доверяют пользовательским
сертификатам без рута или пересборки APK, а iOS позволяет выдать полное доверие штатно.

## 0. Что уже готово

* `mitmproxy 12.2.3` в `tools/.venv-mitm/`
* корневой сертификат создан в `~/.mitmproxy/`
* прокси слушает `0.0.0.0:8080`, веб-интерфейс — `http://127.0.0.1:8081`
* перехваченное пишется в `captures/nis.mitm` (папка в `.gitignore`)

Запустить заново, если выключился:

```bash
tools/.venv-mitm/Scripts/mitmweb.exe --listen-host 0.0.0.0 --listen-port 8080 --web-host 127.0.0.1 --web-port 8081 --save-stream-file captures/nis.mitm --set web_open_browser=false
```

## 1. Открыть порт в брандмауэре

Нужны права администратора. В PowerShell **от имени администратора**:

```powershell
New-NetFirewallRule -DisplayName "mitmproxy 8080 (temp)" -Direction Inbound -LocalPort 8080 -Protocol TCP -Action Allow -Profile Private
```

Это открывает прокси для всей локальной сети — временная и вполне реальная дыра.
**Удалить сразу после разведки:**

```powershell
Remove-NetFirewallRule -DisplayName "mitmproxy 8080 (temp)"
```

## 2. Настроить iPhone

Телефон должен быть на том же роутере (компьютер — `192.168.0.174`, проводом).

**Настройки → Wi-Fi → (i) у своей сети → Прокси HTTP → Вручную**
Сервер `192.168.0.174`, порт `8080`, аутентификация выключена.

## 3. Поставить сертификат

**Способ через `mitm.it` на iOS не работает.** Safari принудительно уходит на HTTPS, а по
HTTPS страницу с сертификатом отдать невозможно: чтобы её показать, прокси уже должен быть
доверенным. В логе это выглядит так:

```
server connect mitm.it:443
Client TLS handshake failed. The client does not trust the proxy's certificate for mitm.it
```

**Рабочий способ — перенести файл на телефон напрямую.** Он лежит в
`captures/mitmproxy-ca-cert.crt` (и `.pem`, одно и то же). Это **только сертификат**, без
приватного ключа — ключ остаётся в `~/.mitmproxy/mitmproxy-ca.pem` и никуда не уходит.
Перекинуть можно чем угодно: Telegram в «Избранное», почта себе, облако.

1. Открыть файл на iPhone → «Профиль загружен».
2. **Настройки → Профиль загружен → Установить** (спросит пасскод).
3. **Обязательный шаг, без него ничего не заработает:**
   **Настройки → Основные → Об этом устройстве → Доверие сертификатам** →
   включить переключатель у `mitmproxy`.

Пункт 3 лежит отдельно от установки профиля и его пропускают чаще всего. Установленный, но
не доверенный сертификат выглядит как установленный, а TLS всё равно рвётся.

Сверить отпечаток (первые 32 знака SHA-256 от DER): `38B9CC78F08CED4726E53870356F7DA9`.

Проверить, что доверие заработало: в логе прокси должны пойти строки `GET`/`POST` вместо
`TLS handshake failed`.

## 4. Снять трафик

Перед началом **закрой остальные приложения**: через прокси пойдёт весь трафик телефона,
а не только НИШ. Окно держим коротким, файл остаётся только на диске.

1. Открыть NIS mektep, войти (если попросит).
2. Зайти в оценки, дневник, уведомления, расписание — по одному разделу, не спеша.
3. Выйти из приложения.
4. Сказать мне, что готово.

Смотреть за процессом можно на `http://127.0.0.1:8081`.

## 5. Убрать за собой

1. Снять прокси: **Wi-Fi → (i) → Прокси HTTP → Выкл**.
2. Удалить правило брандмауэра (команда в шаге 1).
3. Убрать доверие сертификату: **Основные → VPN и управление устройством** → удалить профиль
   `mitmproxy`. Оставлять доверенным чужой корневой сертификат не стоит.

## Если приложение откажется работать

Это **certificate pinning** — приложение проверяет не только валидность сертификата, но и то,
что он именно ожидаемый. В веб-интерфейсе это выглядит как оборванные TLS-соединения к
неизвестному хосту.

Плохая новость: в лоб не обойти. Хорошая: **имя хоста в логе всё равно будет видно**, даже
если тело запроса не расшифруется — а это уже половина ответа. Дальше можно посмотреть строки
и конфиги в самом IPA. Если и это не выйдет — закрываем тему и идём по плану с СУШ.
