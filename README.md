# Nis3

Единый кабинет НИШ — расписание, оценки и AI-ассистент поверх СУШ и EduPage.

Расписание, оценки (с разбивкой по темам и калькулятором), файлы ученика НИШ
в одном кабинете — поверх СУШ и EduPage. Backend: Python 3.12 + FastAPI.
Frontend: React + Vite + TypeScript (`apps/web`).

План: `~/.claude/plans/` (утверждён 7 сентября 2026).
Контракты источников (СУШ/EduPage — что реально отдают, а не что должны по
идее): [docs/sources.md](docs/sources.md).

## Запуск (два сервера)

Оба уже настроены — venv для бэкенда и `node_modules` для фронта на месте,
доустанавливать ничего не нужно.

**Терминал 1 — бэкенд**, из корня проекта:

```bash
.venv/Scripts/python.exe -m uvicorn apps.api.main:app --reload --port 8000
```

**Терминал 2 — фронт**, из `apps/web`:

```bash
npm run dev
```

Открыть `http://localhost:5173` — это и есть весь интерфейс (фронт сам
проксирует `/api` и `/auth` на бэкенд, см. `apps/web/vite.config.ts`,
поэтому куки сессии работают без плясок с CORS).

Заглушка Microsoft Store перехватывает голое имя `python`/`node` в некоторых
терминалах — если команда не находится, зови `.venv/Scripts/python.exe`
и полный путь `node`/`npm` явно (`C:\Program Files\nodejs\...`).

## Первый раз

1. На `http://localhost:5173` — экран регистрации. Заводишь аккаунт нашего
   сайта (имя/почта/пароль — свои, не школьные).
2. Попадаешь на Главную. Все карточки честно покажут «не привязан» — это
   ожидаемо, реальных данных пока нет.
3. Шестерёнка в сайдбаре (десктоп) / гамбургер в шапке Главной (моб.) →
   Настройки → у EduPage и СУШ прямо там форма привязки (школа/логин/пароль).
   Пароли вводишь сам, они уходят прямо на наш сервер и там же шифруются —
   никто, включая Claude, их не видит. Если СУШ ответит капчой — не долби
   кнопку, это circuit breaker, нужен ручной вход попозже.
4. После привязки статус в Настройках сам станет «Подключено» — форма
   привязки заменится на «Отключить». Обнови Главную/Расписание/Оценки —
   покажут твои настоящие данные.

## Что проверять по экрану

- **Вход/Регистрация** — оба макета (сузь окно браузера уже 641px —
  переключение на мобильный), «Запомнить меня» (сними — после перезапуска
  браузера кука не должна пережить закрытие).
- **Главная** — расписание на завтра, ближайшие события (СОР/СОЧ/встречи),
  статус СУШ/EduPage внизу сайдбара/в шапке.
- **Расписание** — Список ↔ Неделя, навигация по дням стрелками,
  консультации на неделе, ближайшие 30 дней.
- **Оценки** — четверти I–IV, смена года стрелками, открыть предмет →
  разбивка по темам подгружается отдельно (недолгая пауза — это реальный
  второй запрос к СУШ, не баг), калькулятор 🤔 — двигай баллы по темам,
  процент и оценка наверху должны пересчитываться на лету, не после отправки
  куда-либо.
- **Файлы** — загрузить/удалить фото (кнопка ＋), лимит 15 МБ и только
  изображения — попробуй загрузить что-то не то, должна быть понятная
  ошибка, а не пустой провал.
- **Настройки** (шестерёнка в сайдбаре / гамбургер на мобильном) — привязка
  СУШ/EduPage (форма прямо там, реальный вызов источника), статус, «Отключить»
  (реально отвязывает — проверяется сразу на самой странице), «Выйти из
  аккаунта».
- **Уведомления** (карточка на Главной) — единая лента EduPage за последние
  30 дней: СОР/СОЧ/БЖБ/линейка/собрания и настоящие текстовые сообщения
  вместе, новые по публикации первыми — то же самое, что видно в самом
  приложении EduPage под Notifications. Только чтение, консультации туда
  намеренно не дублируются (уже есть на Расписании).
- **NisAI** — намеренно честная заглушка, не баг (см. ниже).

## Деплой

Один сервис — `Dockerfile` в корне собирает фронт (Vite) и бэк (FastAPI) в
один образ; бэкенд отдаёт собранный фронт как статику с того же origin
(см. `apps/api/main.py` — `/assets` смонтирован из `apps/web/dist`), так что
никакого отдельного CORS-плясания между фронтом и бэком в проде не нужно —
ровно как сейчас в деве через Vite-прокси.

**Куда** (нужен постоянный диск — SQLite и ключ шифрования должны пережить
рестарт контейнера, иначе после каждого редеплоя все привязанные пароли
СУШ/EduPage становятся нечитаемыми): Railway или Fly.io — у обоих есть
persistent volume из коробки и подхватывают `Dockerfile` автоматически.
Render тоже подходит, но постоянный диск там только на платном тарифе.

**Обязательные переменные окружения** (не в `.env`-файле — в секретах
самой платформы):

| Переменная | Что | Как получить |
|---|---|---|
| `VAULT_KEY` | Ключ шифрования паролей СУШ/EduPage (AES-256-GCM) | `python -m apps.api.vault` — сгенерировать **один раз**, сохранить значение и никогда не перегенерировать: смена ключа делает все уже сохранённые пароли пользователей нечитаемыми |
| `DATABASE_URL` | Путь к SQLite на постоянном томе | `sqlite:////data/nis3.db` (четыре слэша — абсолютный путь; смонтировать `/data` как volume) |
| `OPENAI_API_KEY` | Для NisAI | из аккаунта OpenAI, как в деве |
| `OPENAI_MODEL` | Необязательно, дефолт `gpt-4o-mini` | — |

Без `VAULT_KEY`, заданного явно, сервер в деве сам генерирует ключ и
сохраняет его в файл рядом с кодом (`.dev-vault-key`) — в контейнере этот
файл живёт до первого редеплоя и пропадает вместе с образом, так что в
проде это не подстраховка, а гарантированная потеря всех паролей при
следующем деплое. Всегда задавай `VAULT_KEY` руками.

**Шаги:**

1. Сгенерировать `VAULT_KEY` (см. таблицу) и сохранить его отдельно (менеджер
   паролей/заметки) — это единственная вещь, которую нельзя потерять.
2. Завести git-репозиторий (сейчас его нет) и запушить на GitHub — большинству
   хостов для авто-деплоя из `Dockerfile` нужен подключённый репозиторий.
3. На выбранной платформе: новый сервис из репозитория, подключить постоянный
   том на `/data`, вписать переменные окружения из таблицы выше.
4. Первый деплой — зайти на выданный домен, зарегистрироваться, привязать
   свой СУШ/EduPage, убедиться, что данные подгружаются (см. «Первый раз»
   выше — та же проверка, что и в деве).

**Не проверено вживую** — в этом окружении нет Docker, поэтому сама сборка
образа не прогонялась; `pip install` тех же зависимостых в чистом venv и
`import apps.api.main` — прогнаны и работают (см. `pyproject.toml`, там же
раньше не хватало половины реальных зависимостей — `fastapi`, `uvicorn`,
`sqlalchemy`, `cryptography`, `edupage_api` были только в `.venv`, не в
объявленных зависимостях, поймано и исправлено при подготовке к деплою).
Перед реальным продом стоит один раз собрать образ локально
(`docker build -t nis3 .`) и прогнать `docker run` на подставном `.env`.

## Честные пробелы (не баги, решение — не делать сейчас)

- **NisAI** — красивого чата с реальным ответом нет: нужен `ANTHROPIC_API_KEY`
  на бэкенде, его пока нет. Кнопки ведут на заглушку «экран ещё не собран».
  Дизайн уже отсмотрен, добавить — не больше пары часов, когда ключ появится.
- **Отправка сообщений EduPage** — только чтение (см. «Уведомления» выше).
  У самой библиотеки `send_message` есть, но сырой и багованный (открытый
  issue) — сознательно не подключали.
- **Внерасписанные занятия/консультации в ленте Уведомлений** — сознательно
  не показываем: тот же факт (`additional_data.typ == "lesson"`) уже честно
  виден на Расписании через отдельный путь, дублировать под другой подписью
  хуже, чем не показать здесь.
- **Замена учителя** («замена» вместо «отменён» в расписании) — показываем
  только отмену урока (это есть в данных), замену конкретного учителя на
  конкретный урок адаптер пока не сопоставляет.
- **Правка логина/пароля УЖЕ привязанного источника** — только отвязать и
  привязать заново той же формой; редактирования существующей привязки
  «на месте» нет.
